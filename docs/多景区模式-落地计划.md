# 多景区模式 — 落地计划

> **文档用途**：AI 助手从单景区升级为多景区服务的产品口径与分阶段实现说明。  
> **状态**：多景区主线完成；已支持「城市 → 景区」选择（沪 / 深）；深圳当前仅 **绿野公园** 可选  
> **更新日期**：2026-07-22（演示版交互规格）  
> **相关**：[`场景实现对照表.md`](./场景实现对照表.md)、[`mini-program-routes.md`](./mini-program-routes.md)、[`项目现状.md`](./项目现状.md)、[`演示剥离清单.md`](./演示剥离清单.md)

> **正式上线口径（2026-08）**：游客端为一个小程序绑定一个景区，进入客服时已带 `scenicId`，**无手动切换景区**。`scenicId` 等数据结构仍保留。详见 [`演示剥离清单.md` §2](./演示剥离清单.md#2-已确认产品口径多景区)。本文其余章节描述的是**演示版**交互（顶栏切换 / 选园弹层 / 集团入口记忆）。

---

## 1. 目标

在保持游游 IP 与现有首页 UI 风格的前提下：

1. 顶栏支持选择 / 切换当前服务景区  
2. 首页与后续 AI 能力绑定 `scenic_id` 上下文  
3. 区分**集团入口**与**独立景区小程序入口**  
4. 查单等业务仅面向**当前景区门票订单**

---

## 2. 已确认产品口径

| # | 议题 | 决策 |
|---|------|------|
| 1 | 集团入口 | **默认记住上次景区**；独立小程序跳转则带上对应 `scenicId` |
| 2 | 对话中切换 | **一律新会话**（新建 conversation + 清空消息回欢迎态） |
| 3 | 订单跨景区 | 查单 / 开票 / 点评列表均为 **仅当前景区门票订单** |

---

## 3. UI 规格

### 3.1 顶栏（欢迎态 / 对话态均展示）

```
[←]   [头像] 游游 ✨
             [当前景区名称 ▼]     ← 可点
             ● 景区 AI 助手 实时在线
```

- 景区名：次级字号 + 下拉箭头，不抢「游游」主视觉  
- 副标题与在线状态合并为一行（空格分隔，不加 `·`）  
- 不新增 Tab / 底栏导航  

### 3.2 景区切换弹层

- 组件：底部弹层（Vant `Popup`）  
- **先选城市**（上海 / 深圳），再展示该城市下景区列表  
- 列表项：封面图、景区名称、当前选中态（勾选 / 描边）  
- 默认城市：定位最近城市（失败回落上海）；已有当前景区则跟景区所属城市  

### 3.3 切换确认

| 状态 | 行为 |
|------|------|
| 欢迎态 | 直接切换，刷新首页数据 |
| 对话态 | 轻确认「切换后将开启新对话」→ 新会话 + 回欢迎态 |

## 4. scenicId 解析优先级

高 → 低：

1. **URL / 小程序启动参数** `scenicId`（独立景区入口）  
2. **LocalStorage `lastScenicId`**（集团入口记忆；**含首页顶栏切换**）  
3. **当前 conversation.scenicId**（无记忆时的续聊回落）  
4. 无有效值 → **强制弹窗选景区**（未选不渲染景区内容 / 不发消息）

首页与助手共用 `lastScenicId` / `scenicStore`；首页切换景区会写入记忆并同步会话，进入助手欢迎页显示同一景区。

| 入口 | URL 示例 | 行为 |
|------|----------|------|
| 独立景区小程序 | `/chat?scenicId=scenic_hlg` | 强制该景区，并写入 `lastScenicId` |
| 集团入口 | `/chat` 或 `/chat?from=group` | 有记忆则静默进入；无记忆则弹窗 |
| 记忆失效 | 景区下架 / 不在列表 | 清记忆并弹窗重选 |

## 5. 数据模型

### 5.1 城市与景区目录

```ts
interface CityProfile {
  cityId: string
  name: string
  lat?: number
  lng?: number
  enabled?: boolean
}

interface ScenicProfile {
  scenicId: string
  cityId: string
  name: string
  coverUrl: string
  description?: string
  openTime?: string
  address?: string
  enabled: boolean
}
```

Mock：`src/mock/scenic/cities.json`、`src/mock/scenic/list.json`  

选择器：**先选城市 → 再选景区**；默认城市 = 当前景区所属 > 记忆 `lastCityId` > 定位最近城市 > 上海。  
业务数据（活动 / 票 / 订单等）仍只按 **`scenicId`** 过滤，城市不参与 API 筛选。

### 5.2 Conversation（P1）

```ts
interface Conversation {
  conversationId: string
  scenicId: string
  memberId: string
  personaId?: string
  createdAt: string
  updatedAt: string
}
```

- 进入助手且景区已定时创建 / 复用  
- **禁止**同一 `conversationId` 暗改 `scenic_id`  
- 切换景区 → `startNew(scenicId)`  

### 5.3 业务数据挂 scenicId（P2～P3）

| 数据 | 改造 |
|------|------|
| welcome_templates / welcome_questions / recommend_entries | + `scenicId` 或按景区拆分 |
| blocks / activities / tickets / coupon_products | + `scenicId` |
| Order | + `scenicId`（门票所属景区） |
| 天气 | `Record<scenicId, ScenicWeatherMock>` |
| 规则引擎 | 增加字段 `scenicId`（eq） |

### 5.4 持久化 Key

```text
scenic_{memberId}_last_scenic_id     // 上次景区
scenic_{memberId}_last_city_id       // 上次城市（选择器默认）
scenic_{memberId}_conversation       // P1：{ conversationId, scenicId }
scenic_{memberId}_chat_{scenicId}    // P1 起聊天按景区分桶（可选）
```

## 6. 请求上下文（P1）

`src/api/request.ts` 拦截器默认注入：

```http
X-Scenic-Id: {currentScenicId}
X-Conversation-Id: {conversationId}
```

所有后续 AI / 业务 Mock API 按 Header 过滤。

---

## 7. 订单「仅当前景区」（P3）

- `GET /api/order/list`：按 `X-Scenic-Id` 过滤  
- `order_query` Workflow / Tool：只返回当前景区订单  
- 开票 / 点评可操作列表：同上  
- 欢迎规则 `hasPendingVisitOrder` / `hasInvoiceableOrders` 等：基于过滤后订单集
