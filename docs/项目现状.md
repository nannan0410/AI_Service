## 已完成

### AI 对话与 Tool Calling

- 10 个 Tool + `ToolProcessPanel` 步骤展示
- Skill 关键词路由 + **P0-2 语义补全**（`ticket_purchase` / `travel_guide` / `order_query` 等）
- **Workflow 层（代码正则，优先于 Skill）**：新客领券、购票、游玩攻略（含 **园内路线 `in_park`**）、订单查询、**发票服务**、停车缴费、**演出推荐**、主动营销、服务点评、**园区打卡**、**虚拟排队推荐**、天气人流适合度、附近项目等
- **主对话分层**：寒暄本地秒回；主模型约 30s 超时兜底；**无独立脏话层**（不当用语依赖模型策略，非本仓规则）
- **NLU 增强（有 API Key）**：P0-1 购票槽位、P0-2 Skill 路由（含高置信进 Workflow）、P0-3 攻略子意图
- 业务卡片：Ticket / Coupon / Order / Content / Activity / Guide / VisitorPicker / PageGuide / Review / **scene_recommend**
- 单条消息框：领券、攻略、开票引导、餐饮零售/演出推荐等 **文案 + 卡片 + 操作按钮** 同气泡
- 聊天 UI：客服气泡最大宽度（距游客消息 20px）、卡片内容自动换行
- **推荐两类现状**：① 标签类（订单/会员/AI 写回等画像）可出「因…推荐」；② 定向类现仅「歇脚推荐」；天气/客流为问答+Hero，尚未做成项目卡定向角标。解释层开关 `showExplainReasons` 为**演示专用**（正式 PC 后台 UI 配置不上该字段）
- **欢迎页在园自报（落地规则）**：无**当日**订单（含 OTA）∧ 票夹无**当日**票（实名倒查，含他人代买）∧ 未授权定位 → 询问是否在园；详见《对话意图》§1.3
- **购票资格确认**：含儿童/老人时出票前整批是/否（身高≤阈值 / 满 N 周岁）；否→并入成人再匹配（含套票）；详见《对话意图》§1.4
- **景区点评（优化）**：去订单强绑定；准入=已核销单∨已核销票∨在园（含自报）；景区日限 1 次；推荐项目子项；分享后发券（须 >20 字+≥2 图）；详见 [`景区点评优化规格.md`](./景区点评优化规格.md)

详见 [`对话意图识别与LLM分工.md`](./对话意图识别与LLM分工.md) §1 / §1.1 / §1.2 / §1.3 / §1.4。

### 新客领券

- `runNewGuestCouponWorkflow` + `canClaimNewGuestCoupon` 规则字段
- 四种回复：成功 / 已领取 / 非新客 / 超领取窗口

- `POST /api/coupons/issue`（`purpose: claim | purchase`）

### 购票闭环

- 多轮对话：问人数 → 问日期 → **含儿童/老人时资格是/否卡** → 可闭环则推荐卡；**不可闭环则兜底 + 跳购票列表**
- **3大1小 / 1大1小** 等无精确套票：成人票+儿童票购物车合并下单（套票不与单品混单）；含老人且满龄有老人票 SKU 时可组合；身高/年龄不达标则并入成人再匹配
- 儿童超限固定提示改推成人票（家庭套票同理）；老人未满龄同理
- **推荐成功**：营销券（`cp_prod_purchase`）与票卡同框级联（`offerCoupon` + `revealCount`）；复合推荐（如附近项目）亦同框逐条显现
- 2大0小 = 成人票×张数；2大1小 = 家庭套票
- 草稿不含游客；`/order/submit` 页选手实名出行人后支付；Mock 支付成功 → **`/orders?tab=1`**（待出行/已完成 Tab）

## 已知注意点

- Mock 变更（尤其 `mock/_utils.ts`）需 **重启 dev server**；`src/mock/products/*.json` 变更会触发 Mock 重载（见 `vite.config.ts`）
- 业务配置若被 `/config/business` **LocalStorage 覆盖**，改 JSON 默认后需在后台点「恢复 JSON 默认」才生效
- `demo_new` 注册日 Mock 会在超窗且未领券时自动刷新为「昨天」
- 未配置 `VITE_SILICONFLOW_API_KEY` 时使用离线 Tool fallback
