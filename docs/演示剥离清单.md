## 1. 标签说明

| 标签 | 含义 |
|------|------|
| **保留** | 正式上线仍需要的能力 / 数据结构 / 交互逻辑 |
| **替换数据源** | 能力保留，Mock / 写死数据改为真实 API 或配置中心 |
| **删除游客交互** | 游客端 UI/动作去掉；底层字段或调试能力可另议 |
| **正式环境删除** | 正式包 / 生产环境不得出现（可留在演示仓） |
| **接真能力** | 现为假页 / Mock 闭环，正式接支付、税控、定位等 |
| **本期不上** | 演示或规划里提过，正式首发不做 |

每条建议字段：`演示现状` → `正式目标` → `落地动作`。

## 2. 已确认产品口径：多景区

### 2.1 结论（2026-08-03）

| # | 议题 | 正式上线口径 |
|---|------|----------------|
| 1 | 小程序与景区 | **一个小程序绑定一个景区**（如奇趣乐园、海洋公园各为一个小程序） |
| 2 | 进入 AI 客服 | **天然携带该园 `scenicId`**（启动参数 / 构建配置 / 宿主注入），无需游客再选 |
| 3 | 游客端切换景区 | **没有手动切换景区的动作**（无顶栏 ▼、无选园弹层、无强制选园） |
| 4 | 景区数据结构 | **保留**（`ScenicProfile`、`scenicId`、按园过滤 API、会话绑定景区等） |
| 5 | 演示仓多园切换 | **仅演示 / 联调**：一个 H5 验收多园差异；正式游客包关闭切换入口 |

> 与 [`多景区模式-落地计划.md`](./多景区模式-落地计划.md) 的差异：该文仍描述「集团入口可切换 / 无记忆弹窗选园」。正式游客端以**本清单 §2**为准；「集团入口跨园切换」标为 **本期不上**（若未来有集团 App 再开）。

### 2.2 分层对照

| 层 | 演示版 | 正式上线 |
|----|--------|----------|
| 数据 | 多园 Mock 目录 + `scenicId` 过滤 | 同结构；主数据来自后台 / 中台 |
| 注入 | 顶栏切换 / LocalStorage `lastScenicId` / URL | 小程序启动即写入当前园 `scenicId` |
| 游客 UI | 可点景区名 → `ScenicPickerSheet` | 可只读展示园名，**不可切换** |
| 会话 | 切换园 → 新会话 | 无切换；会话始终本园 |
| 配置后台 | 可按园预览 / 筛选 | 运营可管多园配置（后台能力，非游客切换） |

### 11.1 B-12 与 B-13 共用「LLM 不可用」判定（建议实现口径）
