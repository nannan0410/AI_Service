## 1. 问题背景

智能对话工具真实落地时，需要对接后台与底层系统数据。是否需要一个地方维护：

- **触发条件（标签 / 规则）**
- **展示字段项**

**结论：需要系统性地维护，但不建议全部塞进一个配置文件，应分层、分域维护。**

| 维度 | 示例 | 变更频率 |
|------|------|----------|
| 触发条件 | 新客标签、在园、有待出行订单（`visitDate >= 今天`） | 运营 / 产品 |
| 数据能力 | 调哪些 API、字段从哪来 | 后端 / 集成 |
| 展示字段 | 券卡片显示满减条件 | 产品 / 前端 |

---

## 2. 推荐生产架构（四层）

```
① 元数据目录（Tag / Field Catalog）
   ↓ 引用
② 场景配置（Skill / RecommendEntry / welcome_templates）
   ↓ 调用
③ 数据适配层（Tool Handler + API Binding）
   ↓ 格式化
④ 展示模板（Card Schema / View Config）
```

## 2.1 Skill 场景 vs 欢迎页推荐入口

| 维度 | **Skill 场景**（`skills.json`） | **推荐入口**（`recommend_entries.json`） |
|------|--------------------------------|------------------------------------------|
| **定位** | 对话侧的**能力单元**（能做什么） | 面向游客的**运营入口**（推什么、怎么点） |
| **维护者** | 产品 / 技术（能力边界） | 运营 / 产品（文案、规则、优先级） |
| **核心字段** | `triggerKeywords`、`tools`、`promptAddon` | `title`、`icon`、`rules`、`promptHint`、`skillId` |
| **触发方式** | 用户**发消息后**关键词匹配路由 | 欢迎页**展示 chips**，用户点击后发起对话或跳页 |
| **是否含正文** | 否，只定义调哪些 Tool | 否，只有标题与 prompt 提示语 |
| **与用户状态** | 不直接判断（路由看消息文本） | **规则引擎**按 persona / 在园 / 订单等过滤 |
| **一对多关系** | 1 个 Skill 可被多个入口引用 | 多个入口可指向同一 `skillId` |

- **Skill ≈ 实际功能**：Tool 列表、LLM 指令、Workflow。
- **推荐入口 ≈ 展示**：标题、图标、出现时机；点击发 `promptHint` 后进对话路由。

## 2.2 欢迎页静态文案（`welcome_templates.json`）

| 维度 | `welcome_templates.json` | `recommend_entries.json` |
|------|--------------------------|---------------------------|
| 展示位置 | 欢迎区 **「游游推荐」**（默认 3 条 + 展开，最多 6 条） | 欢迎区 **「快捷服务」** chips（最多 4 条） |
| 个性化 | 按 `personaId` 三份模板 + **订单占位符**（`{{pendingVisitSubtitle}}` 等） | 按 **规则表达式** 动态命中 |
| 后台编辑 | `/admin/business` → 游游推荐 | `/admin/business` → 快捷服务 |
| **当前 Chat 页** | ✅ **已接入**（含「今日出行」副标题） | ✅ **已接入**（Phase C） |

**占位符**（`welcomeTemplateVars.ts`）：`{{nickname}}`、`{{nextVisitDate}}`、`{{upcomingVisitOrderCount}}`、`{{pendingVisitSubtitle}}`。出行日当天 `pendingVisitSubtitle` = **「今日出行」**。

## 2.5 运行时：意图识别与对话路由

用户发消息后，**不只有 Skill 的 `triggerKeywords`**。演示版为 **Workflow 正则（代码）优先 → Skill 关键词 → LLM / 离线 Tool**。

### 2.5.1 总流程（`ChatPage.vue` → `onSend`）

> 完整对照表与「购票为何不用 LLM」说明见 [`对话意图识别与LLM分工.md`](./对话意图识别与LLM分工.md)。

```
用户输入文本
    │
    ├─① Workflow 层（代码正则，最高优先级）
    │     isNewGuestCouponClaimIntent      → runNewGuestCouponWorkflow
    │     ticket_purchase + 购票正则        → runTicketPurchaseWorkflow
    │     travel_guide + 攻略正则           → runTravelGuideWorkflow
    │     order_query + 订单正则            → runOrderQueryWorkflow
    │
    ├─② 未命中 → sendChatMessage
    │     skillStore.resolveSkill(text)     // skills.json triggerKeywords
    │     → LLM + Tool Calling（或离线 fallback）
    │
    └─③ formatters → 业务卡片 / 单条消息框回复
```

**要点：** 新客领券 **无独立 Skill**，不读 `triggerKeywords`；命中 Workflow 后 **不走 LLM**。

### 2.5.2 四层配置对照

| 层级 | 作用 | 配置方式 | 主要文件 |
|------|------|----------|----------|
| **Workflow 意图** | 固定流程（领券 / 购票 / 攻略 / 订单） | **代码正则** | `src/utils/newGuestCoupon.ts`、`src/ai/workflow/*.ts` |
| **Skill 路由** | LLM 用哪个 Skill、哪些 Tool | **`triggerKeywords`**（后台可改） | `skills.json`、`src/ai/skills/router.ts` |
| **欢迎页入口** | chip / 猜你想问 **是否展示** | **规则引擎** | `recommend_entries.json`、`field_catalog.json` |
| **欢迎页文案** | 点击后 **固定 prompt** | JSON | `welcome_templates.json` |

### 2.5.3 Workflow 意图（代码正则）

| 场景 | 判断函数 | 示例说法 | 结果 |
|------|----------|----------|------|
| 新客领券 | `isNewGuestCouponClaimIntent` | 领新客券、领新人券 | 单券 Workflow |
| 交通指南（单篇） | `isTrafficGuideIntent` | 交通指南、怎么去、怎么到景区、停车位置 | `getContentBlocks(traffic)` |
| 入园提醒（单篇） | `isEntryNoticeIntent` | 入园须知、入园提醒、要带什么、几点到 | `getContentBlocks(entry_notice)` |
| **园内路线推荐** | `isInParkRouteIntent` | 在园区内、现在先玩哪里、根据排队推荐今日路线 | `generateTravelGuide(scope=in_park)`，**不含**交通/入园 |
| 组合游玩攻略 | `isFullTravelGuideIntent` 等 | 游玩攻略、按订单做攻略、近期出游 | `generateTravelGuide(scope=full)` |
| Skill 语义路由（P0-2） | `resolveSkillRoute` + `skillWorkflowGate` | 关键词未命中 → LLM；confidence≥0.8 可进 Workflow |
| 攻略子意图（P0-3） | `resolveTravelGuideIntentRoute` | 泛化说法 | LLM 细分 traffic / entry / full |
| 购票槽位（P0-1） | `resolvePurchaseSlotsFromMessage` | 人数+日期口语 | **LLM 优先**（带 session 上下文），失败/无 Key 时正则兜底 |
| 购票 | `shouldRunTicketWorkflow` | 两大一小、买票、套票 | 购票 Workflow |
| 订单查询 | `shouldRunOrderQueryWorkflow` | 查订单、我的订单 | 订单 Workflow |

**修改交通/入园说法：** 改 `src/utils/travelGuideIntent.ts`；泛化说法子意图见 `src/ai/nlu/resolveTravelGuideIntent.ts`（P0-3）。  
**修改园内路线说法：** 改 `isInParkRouteIntent`（对齐 `welcome_templates.json` demo_vip「现在先玩哪里」等 prompt）。  
**修改新客领券说法：** 改 `src/utils/newGuestCoupon.ts` 内正则。  
**修改购票/攻略说法：** 改对应 `src/ai/workflow/*.ts` 与 `src/ai/nlu/*`。

## 3. 配置 Schema

### 3.1 元数据 — `field_catalog.json`

规则字段：`fieldId`、`valueType`、`ruleEligible`；标签：`tagId` + `demoPersonas`。

**推券相关字段：**

| fieldId | 含义 |
|---------|------|
| `canClaimNewGuestCoupon` | 是否可展示/领取新客券（身份 + 窗口 + 未领过） |
| `hasNewGuestCoupon` | 账户是否有 **可用** 新客专享券 |

### 3.2 Skill — `skills.json`

Phase A 已支持后台编辑：enabled、triggerKeywords、tools、promptAddon。

**触发关键词规则（后台 `/admin/business`）：**

| 规则 | 说明 |
|------|------|
| 子意图展示 | 只读目录 `skill_intent_catalog.json`，Skill 详情内展示各子意图及识别词 |
| 子意图词不可删 | 自动并入 `triggerKeywords`，标签带 🔒 |
| 全局唯一 | 同一关键词只能属于一个 Skill，保存时报错 |
| 超集约束 | `triggerKeywords` 须包含该 Skill 全部子意图关键词 |

校验实现：`src/utils/skillKeywordValidation.ts`；目录：`src/utils/skillIntentCatalog.ts`。

### 3.3 推荐入口 — `recommend_entries.json`

```typescript
interface RecommendEntryConfig {

  priority: number
  enabled?: boolean
  rules: RuleExpression[]
}
```

## 12. 智能购票场景（多轮 Workflow）

> 首次购票指引与老客购票共用 **`ticket_purchase` Skill + 多轮 Workflow**；会话状态由 `purchaseStore` 维护。

### 12.1 对话步骤

| 步骤 | 动作 | 说明 |
|------|------|------|
| 1 | 问人数 | 几人出行、是否有老人/小孩；可分步收集 |
| 2 | 问日期 | 具体日期或模糊说法（这周末、下周） |
| 3 | 解析日期 | `visitDateParser.ts`：模糊时段取距今天最近且 **≠ 当天**；**下周末/下个周末** 优先于「周末」 |
| 4 | 主动营销 | 无 **可用** 新客券时 `issueCoupon(cp_prod_purchase)` |
| 5 | 推荐产品 | 可闭环 → 单 SKU 推荐卡；不可闭环 → **兜底话术 + 购票列表按钮**（见 §12.5） |
| 6 | 确认下单 | 仅 `recommend` 步：点击推荐卡按钮 → `createOrderDraft` → `/order/submit` |
| 7 | 下单页 | `/order/submit` 选手实名出行人 → Mock 支付 → **`/orders?tab=1`**（待出行/已完成 Tab） |

### 12.2 选品规则（`matchPartyToProducts`）

| 人数 | 结果 | 说明 |
|------|------|------|
| 2 大 1 小 | `single` | 家庭套票 `tkt_family` |
| N 大 0 小 | `single` | 成人票 `tkt_adult` × N |
| 3 大 1 小、1 大 1 小 等 | `multi_product` | 需多 SKU 组合，助手 **不支持购物车** |
| 含老人且无老人票 | `no_product` | 提示无符合规则产品 |

**卡片推荐标签：** `tickets.json` → `recommendLabel`；留空则不显示。

### 12.5 无法闭环兜底

| 分支 | 对话提示 | UI |
|------|----------|-----|
| `no_product` | 当前没有符合规则的可售产品 | `ticket_fallback` 卡 +「去购票列表选购」→ `/tickets` |
| `multi_product` | 查到多款产品，但不支持购物车合并下单 | 同上；可展示参考组合明细 |

- **专用券：** `cp_prod_manual` 购票优享 5 元券（与停车 `cp_prod_parking` 等同为 5 元但 **券产品 ID 不同**，互不冲突）
- **识别与去重：** 券实例带 `couponProductId`；`findFallbackPurchaseCoupon()` / Mock `issueCoupon` 均按 **产品 ID** 判定，不按金额或标题
- **展示：** 进入兜底时 **始终展示** 优享券卡片；账号尚无可用 `cp_prod_manual` 时调用 `issueCoupon` 新发，已有则复用展示、不重复入库
- **与购票 10 元券区分：** 10 元券（`cp_prod_purchase`）仅在 `single` 推荐成功路径推送；5 元优享券仅在 fallback 路径
- **关键文件：** `partyProductMatch.ts`、`purchaseFallbackCoupon.ts`、`TicketFallbackCard.vue`、`TicketsPage.vue`

### 12.3 优惠券逻辑（可闭环路径）

- **主动营销：** `shouldPushPurchaseMarketingCoupon()` — 账号无新客券，或新客券已用/已过期 → 发购票10元券
- **抵扣计算：** `pickBestCoupon()` — 账号可用券（含刚发的营销券）取最高抵扣；优惠价 = 原价 − 抵扣
