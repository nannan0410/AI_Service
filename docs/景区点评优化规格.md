# 景区点评优化规格

> **状态**：定稿（演示落地中）  
> **日期**：2026-08-12  
> **关联**：[`对话意图识别与LLM分工.md`](./对话意图识别与LLM分工.md)、[`业务场景配置与实现.md`](./业务场景配置与实现.md)、[`项目现状.md`](./项目现状.md)

---

## 0. 目标与边界

将点评从 **按订单评价** 改为 **游园日景区点评**：收集图文运营资产，引导外部分享；激励与分享挂钩，优质内容有硬门槛。

| 做 | 不做（本期） |
|----|----------------|
| 景区整体点评（去订单强绑定） | 项目点评（见 §8） |
| 准入 OR + 自然日 1 次 | 真接微信/抖音等分享 SDK（Demo 统一 Toast） |
| 推荐游玩项目子项 | 「优质」标签与置顶（预留） |
| 分享后发券（日限 1 次） | 与打卡合并的项目页入口 |
| 点评管理 +「在小程序展示」 | |

---

## 1. 可操作前提与日限

### 1.1 准入（OR，任一即可）

| # | 条件 | 说明 |
|---|------|------|
| 1 | 有 **已核销订单** | 当前景区；演示用 `status=completed` 近似 |
| 2 | 票夹有 **已核销门票** | 正式：实名倒查；演示可用已核销订单/票务 Mock 近似 |
| 3 | **识别在园** | 系统信号；**在园自报算在园**（与欢迎区 live `inPark` 一致） |

### 1.2 日限

| 项 | 口径 |
|----|------|
| 维度 | **账号 + 景区 + 景区时区自然日**（演示可用本地日近似） |
| 点评 | **每天提交 1 次** |
| 分享 | **每个平台每天 1 次**（朋友圈 / 小红书 / 抖音 / 大众点评） |
| 发券 | **每天最多发点评奖励 1 次**（与多平台分享解耦） |

规则字段：`canScenicReviewToday` = 准入 ∧ 今日未点评。  
（旧字段 `hasReviewableOrders` 可保留兼容预览，入口逐步切到 `canScenicReviewToday`。）

---

## 2. 表单（去订单）

- **不选订单、不强制 `orderId`**
- 字段：星级、标签、文案（≤200）、图片、「帮我写评价」
- 新增：**推荐游玩项目**
  - 园区无项目 → **整项隐藏**
  - 有项目 → 展示；带 **「热门」** 标签的优先/角标
  - 多选（演示上限 5）
- 提交体：`scenicId`、`rating`、`tags`、`content`、`imageIds`、`recommendedActivityIds[]`

---

## 3. 优质门槛（发券基础条件，硬性）

必须同时：

- 文案 **> 20 字**
- 图片 **≥ 2 张**

未达标：仍可提交（若当日未评），**不可因分享发券**。

---

## 4. 提交后分享

成功后展示：

1. 感谢文案  
2. 引导语：可同步分享到其他 App  
3. **分享** → 底部四项（全部展示）：朋友圈 / 小红书 / 抖音 / 大众点评  

**演示点击统一行为：**

- Toast：`根据接口规则进行分享跳转并记录分享成功`
- 该渠道分享计数 +1（每平台每日一次）
- 若已达优质门槛且当日未发券 → 发券

正式版预留按渠道配置：标题/正文模板、`{scenicName}`、话题（如小红书 `#景区名`）、deeplink、图片策略等（`share_channels` 配置）。

---

## 5. 发券时机

```
提交点评（不写订单 reviewStatus 为主路径）
  → 用户触发「某平台分享成功」
  → 内容已达优质门槛（>20 字 + ≥2 图）
  → 且当日尚未发过点评奖励
  → issue 点评券（餐饮 + 停车，沿用现产品 ID）
```

提交瞬间 **不发券**。

---

## 6. 点评管理（运营资产）

- 页面名：**点评管理**
- 列表：景区点评记录（内容、图、项目、状态、分享渠道、是否已发券）
- 操作：**在小程序展示**（开关；打开后小程序精选/列表可露出）
- **本期不做**人工「优质」标签；扩展：优质标签 → 小程序置顶
- 定位：图文收集的运营资产，非纯客服工单

---

## 7. Demo API / 存储（摘要）

| API | 说明 |
|-----|------|
| `GET /api/reviews/eligibility` | 是否可评、今日是否已评、优质提示 |
| `POST /api/reviews/submit` | 无强 orderId；写景区点评；返回 `qualityEligible`；**不发券** |
| `POST /api/reviews/share` | `{ reviewId, channel }`；Toast 语义；计数；条件发券 |
| `GET /api/reviews/admin` | 点评管理列表 |
| `POST /api/reviews/admin/display` | `{ reviewId, showOnMiniProgram }` |

运行时按 persona 存：`scenicReviews[]`、`reviewRewardDateByScenic`、分享日记录。

## 8. 后续扩展（项目点评 × 打卡）

| 项 | 说明 |
|----|------|
| 项目点评 | 对象 `activityId`；入口偏 **小程序项目详情** |
| 与打卡 | 打卡成功后可选短评；日限与同点打卡协调；避免与景区日评激励重复领 |
| 优质标签 | 点评管理增加标签；小程序置顶 |
| 真分享 | 按渠道配置话题 / deeplink / 海报 |

本期 AI 对话入口仍以 **景区点评** 为主，不抢项目页入口。

---

## 9. 验收（演示）

| # | 操作 | 预期 |
|---|------|------|
| 1 | 无核销、不在园、未自报 | 不可点评 |
| 2 | 自报在园或有已完成单 | 可进点评；表单无订单选择 |
| 3 | 有热门项目的景区 | 可见「推荐游玩项目」 |
| 4 | 当日已提交 | 不可再提交 |
| 5 | 提交未满 20 字/2 图后分享 | 分享计数 +1，不发券 |
| 6 | 达标后首次分享 | 发券；同日再分享其他平台不再发 |
| 7 | 点评管理打开「在小程序展示」 | 记录可展示 |
