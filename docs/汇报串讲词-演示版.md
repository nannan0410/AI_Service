## 二、完整串讲词（可照读）



### 1. 开场

各位好。下面由我为大家演示我们的 **AI 景区智能聊天助手方案**。

首先它区别于普通的问答机器人，定位是 **「AI 智慧景区运营入口」**：用对话把游前、游中、游后串起来——购票、攻略、排队、推券、开票、点评，都能在一个对话里完成入口；真正要下单、缴费、批量开票这些重操作，再跳到 H5 / 小程序假页闭环。

当前版本约在 **v0.2.x**，数据是 Mock，可接硅基流动 LLM；重点是 **可演示、可验收、可配置**。

---



### 2. 架构怎么讲（避免陷入代码）

用户发一句话之后，系统大致三层：

1. **Workflow（代码规则，优先级最高）**
  领券、购票状态机、发票、停车、虚拟排队、演出场次、「今天适不适合玩」等——要求 **可预测、可审计**，不交给大模型随便发挥。
2. **Skill 关键词 + 可选 NLU 语义补全**
  说法不标准时，有 API Key 可以语义补一下，再进对应 Workflow。
3. **未命中再走 LLM + Tool Calling**
  兜底通用对话；没有 Key 时有离线正则演示兜底。

一句话总结：**能规则化的业务走规则；LLM 做理解补全和通用对话，不算价、不乱发券。**

欢迎页的快捷服务、猜你想问，是另一套 **规则引擎**：按账号、是否在园、有没有待出行 / 可开票订单等字段显隐，后台 `/config` 可改。

（需要投影时，可对照 `[对话意图识别与LLM分工.md](./对话意图识别与LLM分工.md)` 总路由图。）

### 3. 游前串讲（边操作边说）

**【切到 demo_new】**

先看游前。打开欢迎页，上方有 **当日景区天气 Mock**，下面是快捷入口和「游游推荐」——这些都会按游客画像过滤，不是写死一排按钮。

**动作：** 点或输入「领新客券」  
**串讲：** 新客领券走独立 Workflow：成功 / 已领 / 非新客 / 超领取窗口，四种结果都可演示。发券是规则判定，不是模型随便发。

**动作：** 「首次购票」或购票相关说法 → 问人数 → 日期 → 出票卡 → 确认 → 假页选游客支付  
**串讲：** 购票是多轮状态机。2大1小进家庭套票；无精确套票的成人+儿童（如 3大1小）走购物车合并下单；含老人等无法匹配才兜底票务列表。有营销券时与票卡同框出现。确认靠卡片按钮，不靠用户打字「确认」。

**动作：** 「出行前要准备什么？」或交通 / 入园类问题  
**串讲：** 游玩攻略按子意图拆：交通、入园须知、游玩推荐、完整攻略、园内路线，内容来自配置化内容块。

**动作（可选亮点）：** 「今天适合游玩吗」  
**串讲：** 这是独立于宽泛攻略的天气人流适合度：当日天气 + 人流档位 + 一句话建议，避免和「怎么去」「玩什么」抢意图。

会员场景可切 **demo_vip + 奇趣乐园**：「会员专属怎么买最划算」→ 等级折扣 + 券 + 标签选品，一卡组合价。

---



### 4. 游中串讲

**【切到有在园态的账号，如 mid / vip 在园】**

游中重点是 **在园才开放** 的能力。

**动作：** 「今天有演出吗」/「演出推荐」  
**串讲：** 演出场次优先于泛攻略；当日 / 明天后天 / 通用推荐逻辑分开，结果是文案 + 演出卡同气泡。

**动作：** 「虚拟排队」→ 免费取号；或「快速排队」→ 付费；或「过山车」点名  
**串讲：** 仅在园可用；支持免费包、付费单、项目名模糊匹配。对话给推荐卡，取号 / 支付进假页。

**动作：** 「我要打卡」  
**串讲：** 对话引导到打卡页，同点日限一次，积分 / 小券 Mock。

**动作：** 「附近有什么好吃的」类餐饮 / 伴手礼  
**串讲：** 餐饮零售推荐：在园可顺势推券，非在园只推店铺，避免游前乱发游中券。

海洋公园可补一句：**答题不单独冷启动**，挂在海豚表演场次或企鹅 / 白鲸介绍上，全对发券加积分——互动和内容绑定。

---



### 5. 游后串讲

**【demo_vip，当前景区有可开票 / 可评订单】**

**动作：** 快捷「开发票」或说「开发票」  
**串讲：** 查当前景区 90 天内可开票订单；有则「立即开票」进批量开票假页，没有就明确提示。对话只做入口，不开真实税控。

**动作：** 「我要点评」→ 选星级标签 →「帮我写评价」→ 可改再提交  
**串讲：** 入口是规则；帮写评价有 Key 走 LLM，否则离线模板；草稿不自动提交。优质评价（字数 + 图）仍可发点评券。

**动作：** 「交停车费」  
**串讲：** 查绑定车牌，引导停车缴费页；未绑则引导绑定。

---



### 6. 收尾：进度与边界

对照规划，**游前主链路基本齐**：领券、购票、攻略、订单查询、会员选品。  
**游中**：演出、虚拟排队、打卡、餐零售推券、答题挂靠已通；**一键路线串联打卡奖励**还没做。  
**游后**：开票、点评、停车已通。

明确本期不做 / P3 的：欢迎页主动弹券、地理围栏离园推券、OCR 小票对话接入、失物招领等。

下一步可按业务优先级补：路线串联、天气接真 API、主动触达类推券，以及正式版把意图服务从演示正则迁到后端。

以上是演示版能力边界和已验证闭环，欢迎提问或指定场景深挖。

## 五、可能被问到的三句答法

1. **为什么购票不用 LLM？**
  选品、算价、发券要可审计；LLM 只补人数 / 日期等槽位。
2. **和普通客服 Bot 差在哪？**
  有游客态（新客 / 在园 / 可开票）、有业务卡片与假页闭环，不是纯文本。
3. **正式版怎么演进？**
  Mock → 真接口；正则意图 → 后端意图服务；P3 再做主动触达。
