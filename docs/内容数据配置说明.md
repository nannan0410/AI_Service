# 内容数据配置说明

> 记录演示版中「交通指南 / 入园提醒 / 游玩攻略 / 园区推荐」等内容数据的维护位置、数据模型与拼装逻辑。  
> 当前实现以 Mock JSON + vite-plugin-mock 为主，**尚无独立 CMS 后台**。  
> **更新日期**：2026-07-22（含虚拟排队对话 API、欢迎天气 Mock、`welcome_questions` 规则模型）

---

## 1. 内容分类与维护原则

| 场景 | 数据形态 | 维护方式 |
|------|----------|----------|
| 交通指南 | **单篇内容** | `blocks.json` 中一条 `type: traffic` |
| 入园提醒 | **单篇内容** | `blocks.json` 中一条 `type: entry_notice` |
| 游玩攻略 | **多项组合** | 运行时由 `generateTravelGuide()` 拼装 |
| **园内路线** | **精简组合** | `generateTravelGuide(scope=in_park)`：游玩线路 + 游玩建议 + 线路途经（攻略卡） |
| 园区推荐 | **多项组合** | 活动池 `activities.json` + 运行时过滤 |

**入口文案**（欢迎页按钮、猜你想问、RecommendEntry）与**正文内容**分开维护，见 [§5](#5-入口与-skill-配置非正文内容)。

## 2. 单篇内容：ContentBlock

### 2.1 文件

```
src/mock/content/blocks.json
```

### 2.2 字段

类型定义见 `src/types/index.ts` → `ContentBlock`：

```typescript
interface ContentBlock {
  contentId: string
  type: 'traffic' | 'entry_notice' | 'faq' | 'guide' | 'strategy'
  title: string
  body: string
  media?: string[]
}
```

### 2.3 当前示例

| contentId | type | 用途 |
|-----------|------|------|
| `cnt_traffic_001` | `traffic` | 交通指南正文 |
| `cnt_entry_001` | `entry_notice` | 入园提醒正文 |
| `cnt_guide_001` | `guide` | 日程建议素材（用于游玩攻略组合） |

### 2.4 API 与 Tool

| 项 | 说明 |
|----|------|
| API | `GET /api/content/blocks`，可选 `?type=traffic` / `entry_notice` 等 |
| Mock 实现 | `mock/config.ts` |
| Tool | `getContentBlocks` |
| 卡片 | `ContentCard.vue` |

单独问「交通指南」或「入园提醒」时，Workflow 按 `travelGuideIntent.ts` 识别意图（**明确说法走正则**；泛化说法 P0-3 由 `resolveTravelGuideIntentRoute` + LLM 细分），调用 `getContentBlocks(type=traffic|entry_notice)` 返回对应 **1 条** ContentBlock，前端渲染为 ContentCard。组合「游玩攻略」走 `generateTravelGuide(scope=full)`；**园内路线**（如 demo_vip「现在先玩哪里」）走 `scope=in_park`，**不含**交通与入园块。

**正文格式：** `body` 为纯文本，支持 **Emoji 小图标** 与 `\n` 换行；`ContentCard` / `GuideCard` 使用 `white-space: pre-wrap` 保留段落。`media[]` 预留图片 URL，当前演示未使用。

## 3. 组合内容：游玩攻略

### 3.1 拼装逻辑

文件：`mock/_utils.ts` → `generateTravelGuide(personaId, { scope })`

| scope | 组成部分 | 数据来源 | 规则 |
|-------|----------|----------|------|
| `full`（默认） | 交通 | `blocks.json` → `type: traffic` | 取第一条 |
| `full` | 入园提醒 | `blocks.json` → `type: entry_notice` | 取第一条 |
| `full` / `in_park` | 日程建议 | `blocks.json` → `type: guide`（`full`）；`in_park` 由排队排序动态生成「今日游玩线路」 | 映射为 `dayPlan` |
| `in_park` | 游玩建议 | 演示生成 `tips` | 与线路分开展示 |
| `full` / `in_park` | 项目列表 | `src/mock/activities.json` | `full`/`recommend` 为推荐项目；`in_park` 为「线路途经」，最多 4 条 |
| `full` | 订单上下文 | persona 用户快照 | **最近一笔待出行订单**（见 [§3.4](#34-待出行订单与日期规则)） |
| `in_park` | 标题 | 固定 | `今日园内游玩攻略`；**不**附带 visitDate / 交通 / 入园 |
| `recommend` | 推荐项目 | `activities.json` | 不含交通/入园；前期攻略隐藏排队时长（见 [§4.3](#43-项目推荐与攻略场景区分)） |

**触发示例（园内）**：`recommend_entries.json` → `today_route`（「今日推荐路线」）或 `welcome_templates` demo_vip「排队少的项目推荐」；园内 prompt 走 `travel_guide` + `scope=in_park`。

### 3.4 待出行订单与日期规则

演示版以 **系统当前本地日期** 判定待出行，避免 Mock 固定日期过期后仍被推荐。

| 项 | 说明 |
|----|------|
| 工具 | `src/utils/upcomingVisitOrder.ts` |
| 待出行定义 | `status` 为 `paid` 或 `pending`，且 `visitDate >= 今天`（YYYY-MM-DD） |
| 攻略选单 | `mock/_utils.ts` → `pickNearestUpcomingVisitOrder()`，取 **出行日最近** 的一笔 |
| 规则字段 | `hasPendingVisitOrder`、`nextVisitDate`、`upcomingVisitOrderCount`、`hasVisitToday`（`demoRuleContext.ts` / `mock/rules.ts`） |

**demo_mid 订单 Mock**（`src/mock/users/demo_mid.json`）：

| visitDate | 票种 | 说明 |
|-----------|------|------|
| `2026-06-30` | 家庭套票（2大1小）×1 | 出行日当天欢迎页显示「今日出行」 |
| `2026-07-30` | 成人票 ×3 | 6-30 过期后变为最近待出行 |
| `2026-08-18` | 家庭套票（2大1小）×2 套 | 第三笔远期订单（quantity：4 成人 + 2 儿童） |

过期 `paid` 订单仍可在「我的订单」列表查看，但不再参与攻略绑定与 `hasPendingVisitOrder` 规则。

### 3.2 API 与 Tool

| 项 | 说明 |
|----|------|
| API | `GET /api/travel/guide`，园内路线加 `?scope=in_park` |
| Mock 实现 | `mock/business.ts` |
| Tool | `generateTravelGuide` |
| Skill | `travel_guide`（`src/mock/assistant/skills.json`） |
| 卡片 | `GuideCard` + 多张 `ContentCard` + 多张 `ActivityCard` |
| 格式化 | `src/ai/tools/formatters.ts` → `buildTravelGuideCards()` |

### 3.3 返回结构

`TravelGuideResult`（`src/types/index.ts`）主要字段：

- `scope` — `full` | `in_park`（园内路线不含交通/入园）
- `title` / `visitDate` / `ticketName` — 与订单关联的标题信息（`in_park` 通常无 visitDate）
- `traffic` / `entryNotice` — 来自 ContentBlock（仅 `scope=full`）
- `dayPlan` — `full`/`recommend` 来自 `type: guide`；`in_park` 为动态「今日游玩线路」
- `tips` — 仅 `in_park`：游玩建议
- `activities` — 项目列表（`in_park` 为线路途经）

## 4. 组合内容：园区推荐

### 4.1 活动池

```
src/mock/activities.json
```

每条活动主要字段：

| 字段 | 说明 |
|------|------|
| `activityId` / `name` / `location` / `timeRange` / `tags` | 基础展示 |
| `category` | `ride` / `show` / `dining` / `retail` |
| `queueStatus` | `none` / `waiting` / `paused`（暂停排队） |
| `waitMinutes` / `pausedQueueLength` | 排队时长或暂停时队伍长度 |
| `showStartTimes` / `recommendedDuration` | 演出场次、建议游玩时长；对话「演出推荐/今日演出」由 `runShowScheduleWorkflow` 读取并合并为一条 `scene_recommend` |
| `isHot` | 热门项目标记 |
| `virtualQueue` | 虚拟排队（免费/付费） |

虚拟排队订单池：`src/mock/virtual_queue.json`（会话内可变）。

对话推荐 API：`GET /api/virtual-queue/catalog`（在园 + 可排队项目）；取号 `POST /api/virtual-queue/take`；付费 `POST /api/virtual-queue/pay`。假页：`/queue/take`、`/queue/pay`。

### 4.3 项目推荐与攻略场景区分

`src/utils/activityDisplay.ts` 通过 `guideContext` 区分展示：

| guideContext | 对应 scope | 排队信息 | 热门项目 |
|--------------|------------|----------|----------|
| `in_park` | `in_park` | 展示实时排队 | 可选热门标签 |
| `pre_visit` | `recommend` / `full` | **不展示**排队分钟数 | 显示「热门」+ 建议提早前往并预留排队时间 |

攻略生成时由 `generateTravelGuide` 按 scope 设置 `guideContext`；Tool `getScenicActivities` 格式化默认为 `pre_visit`。

### 4.2 API 与 Tool

| 项 | 说明 |
|----|------|
| API | `GET /api/activities`，可选 `?tag=亲子` |
| Mock 实现 | `mock/business.ts` |
| Tool | `getScenicActivities` |
| Skill | `scenic_recommend`（演出场次已启用）；`queue_recommend`（虚拟排队已启用） |
| 卡片 | `ActivityCard.vue`，Tool 格式化时最多取 4 条 |

园区推荐**没有单独的 bundle JSON**；当前为活动池 + 标签过滤，由 Skill / LLM 决定何时调用 Tool。

## 5. 入口与 Skill 配置（非正文内容）

以下内容决定「用户怎么触发」，**不包含**攻略/提醒正文。意图识别分层见 [`业务场景配置与实现.md` §2.5](./业务场景配置与实现.md#25-运行时意图识别与对话路由)。

| 文件 | 定位 | 作用 |
|------|------|------|
| `src/utils/newGuestCoupon.ts` | **Workflow 意图层** | 新客领券；命中后直接跑固定流程，**优先于 Skill** |
| `src/utils/travelGuideIntent.ts` | **Workflow 意图层** | 交通 / 入园 / **园内路线** / 组合攻略 正则分流 |
| `src/ai/nlu/resolveTravelGuideIntent.ts` | **NLU 增强（P0-3）** | 泛化说法 LLM 子意图 |
| `skills.json` | **能力层** | `triggerKeywords` 关键词路由、Tool 白名单、LLM 指令 |
| `recommend_entries.json` | **运营入口层** | 规则化 chips：标题/图标/何时展示；可绑定 `skillId` 或跳页 |
| `welcome_templates.json` | **演示文案层** | 按 persona 的欢迎 **标题区**（title/subtitle/body）；支持订单占位符（见 [§5.2](#52-welcome_templates-占位符)） |
| `welcome_questions.json` | **运营入口层** | 「游游推荐」问题列表；与快捷服务同一套 `rules` |
| `scenicWeather.ts` | **欢迎 Hero** | 当日景区天气本地 Mock（「我是游游」上方一行） |
| `card_views.json` | **展示层** | 卡片字段显隐（Tool 结果 → UI） |

### 5.2 welcome_templates 占位符

欢迎页渲染时由 `src/utils/welcomeTemplateVars.ts` 结合用户订单动态替换：

| 占位符 | 含义 |
|--------|------|
| `{{nickname}}` | 会员昵称 |
| `{{nextVisitDate}}` | 最近待出行日期 |
| `{{upcomingVisitOrderCount}}` | 待出行订单笔数 |
| `{{pendingVisitSubtitle}}` | 游游推荐副标题：**出行日当天为「今日出行」**；否则为 `{日期} 待出行订单已就绪` |

Chat 页加载时会 `fetchOrders()`，与 Mock 快照一致时 demo_mid 在 2026-06-30 当天可见「今日出行」。

### 5.1 关系摘要

```
welcome_questions / recommend_entries  →  用户点击 → 发出 prompt
welcome_templates（标题）+ Hero 天气 Mock
                                              ↓
Workflow 正则（领券/购票/攻略/虚拟排队等）  →  优先命中则固定流程
                                              ↓（未命中）
skills.json triggerKeywords  →  LLM + Tool  →  正文数据（blocks / activities）
```

- **Skill**：1 个能力单元；多个推荐入口可共用同一 `skillId`。
- **推荐入口**：面向游客友好展示 + 规则；`target: chat` 时靠 `promptHint` 进对话，`target: page` 时直接跳路由。
- **welcome_questions**：与 RecommendEntry **同一规则模型**；`welcome_templates` 仅保留标题区文案。
- **欢迎天气**：`src/utils/scenicWeather.ts` 本地常量，可后续接 API。

业务规则与后台编辑：[`业务场景配置与实现.md`](./业务场景配置与实现.md)。

## 8. 与生产 CMS 的关系

演示版将内容放在 Git 管理的 JSON 中；生产环境建议：

- **单篇内容**（交通、入园、FAQ）→ CMS ContentBlock，按 `type` 管理
- **组合场景**（游玩攻略、园区推荐）→ 配置「引用哪些 block + 哪些 activity / 商品」的 bundle，或由 Skill + 规则引擎在运行时拼装

架构分层参考 [`AI景区智能聊天助手-落地计划.md`](./AI景区智能聊天助手-落地计划.md) §4.5 ContentBlock。
